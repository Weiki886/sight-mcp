# Sight MCP v0.2.0 Release Notes

**语言 / Language：** [中文](v0.2.0.md) · English

> Status: preparing for release

Sight MCP v0.2.0 focuses on **reducing authorization friction**: eliminating repeat dialogs for
everyday image paths without relaxing the filesystem boundary.

## What's New

### Client workspace root discovery

When the connected MCP client advertises the `roots` capability (Claude Code does), the server
requests the client's workspace roots after initialization and adopts them as allowed roots. Images
inside the workspace no longer trigger an authorization dialog.

- Background request with a 3-second timeout; every failure (capability absent, protocol era
  unsupported, timeout) degrades silently and never blocks a tool call.
- Only `file://` roots are accepted; each path is canonicalised with `realpath` and must resolve to
  an existing directory.
- The filesystem root `/` and the whole home directory are refused and reported as a warning.
- Nested roots collapse to the minimal equivalent set, matching `SIGHT_ALLOWED_ROOTS` behaviour.
- A client may send `notifications/roots/list_changed` to have the server refresh the set.

**Compatibility note:** `roots/list` is deprecated as of MCP revision 2026-07-28 (SEP-2577) and the
SDK refuses to send it on that era. This capability is therefore implemented as an optional
enhancement, not a hard dependency — the server works normally when a client cannot serve it.

### Session authorization cache

When a path falls outside both the configured roots and the discovered client roots, the macOS
authorization dialog still appears. Once the user approves, however, the **parent directory** of
that path is recorded in an in-process memory cache, so subsequent reads inside the same directory
do not prompt again during the session.

This layer is protocol independent and is the fallback that removes repeat dialogs when root
discovery is unavailable. Security constraints:

- Only the parent directory of the path the user actually approved is cached; the grant never walks
  upward.
- The filesystem root and the home directory are never cached, regardless of path depth.
- Grants live in process memory only, are never persisted, and are cleared on restart.
- Denials and cancellations leave no record in the cache.

### Documentation link CI gate

A new `pnpm docs:check` script, placed at the head of `pnpm run ci`, validates five rules for
bilingual documentation: switch links cross languages with exactly one per document, body links stay
within the same language, no dead links, no absolute paths, and copies are complete.

## Changes

- Release scripts no longer hardcode the version number; they read it from `package.json`, so future
  releases only need to change one place.
- `pack:check` replaced its fixed-version assertion with "packed artifact matches declared version"
  and validates the version format.

## Fixes

- Fixed four language-switch links that pointed to their own `.en.md` file instead of the Chinese
  counterpart. The root cause was perl's `$.` line counter not resetting across files in a
  multi-file edit.

## Threat Model

Two new entries with corresponding tests:

- **FS-05:** Malicious or misconfigured client reports an over-broad workspace root.
- **FS-06:** Session authorization cache widens one approval into a broad grant.

## Installation & Verification

```sh
npx -y @weiki/sight-mcp@0.2.0
npm view @weiki/sight-mcp@0.2.0 dist.integrity dist.tarball
```

## Upgrade Notes

Upgrading from v0.1.0 contains no breaking changes and requires no configuration changes. Tool
contracts, error codes, and environment variables remain compatible.

After upgrading, restart the MCP server in your host to load the new code.
