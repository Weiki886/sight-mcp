# Sight MCP v0.3.0 release notes

**语言 / Language：** [中文](v0.3.0.md) · English

> Status: preparing for release

Sight MCP v0.3.0 removes all built-in Provider profiles in favor of a fully user-configured generic
OpenAI-compatible endpoint. The upstream `deepseek-v4-flash-vision-exp` model has been
decommissioned, and hardcoding models proved unsustainable; from this release on, the endpoint and
model come only from environment variables, so model upgrades, deprecations, and swaps are under
your control and no longer wait for a release. See
[ADR 0004](../adr/0004-generic-provider-configuration.en.md) for the decision record.

## Breaking changes

- The `--provider qwen|deepseek` flag is removed; passing it exits with status `2` and prints
  migration guidance.
- The `SIGHT_QWEN_API_KEY` / `SIGHT_DEEPSEEK_API_KEY` environment variables are removed (no longer
  read).
- `SIGHT_PROVIDER_BASE_URL` and `SIGHT_PROVIDER_MODEL` are now always required (profile users
  previously received them implicitly from a bundled pairing).
- `credentials status` now requires an explicit account name (Keychain cannot enumerate items).

## Migration guide (0.2.x → 0.3.0)

1. Set the endpoint and model explicitly in the host environment. The former qwen profile is
   equivalent to:

   ```text
   SIGHT_PROVIDER_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
   SIGHT_PROVIDER_MODEL=qwen3.8-flash
   ```

2. Remove `--provider` from the host's server arguments.
3. Use `SIGHT_PROVIDER_API_KEY` for environment keys; on macOS, set
   `SIGHT_PROVIDER_KEYCHAIN_ACCOUNT` to your Keychain account name — an existing `qwen` item is
   reused as-is (`SIGHT_PROVIDER_KEYCHAIN_ACCOUNT=qwen`), no re-entry needed.
4. Generic-mode users who never used a profile need no changes.

## Changes

### Provider configuration ([Issue #63](https://github.com/Weiki886/sight-mcp/issues/63))

- Endpoint and model come entirely from `SIGHT_PROVIDER_BASE_URL` + `SIGHT_PROVIDER_MODEL`, so any
  OpenAI-compatible vision endpoint (local or remote) is reachable;
- API key resolution order is fixed: `SIGHT_PROVIDER_API_KEY`, then the macOS Keychain item named by
  `SIGHT_PROVIDER_KEYCHAIN_ACCOUNT` (new); with neither set, the endpoint is treated as
  unauthenticated; an explicitly named but missing/unreadable account fails startup closed;
- Credential commands generalize to arbitrary account names:
  `credentials set|status|delete <account> [--yes]`, with a validated character set (1-64
  characters); the Keychain service name is unchanged and existing items are preserved;
- The host smoke script's `--profile qwen|deepseek` becomes `--live` (endpoint, model, and key are
  injected entirely through the runner's environment variables);
- README, configuration specification, threat model, testing strategy, Provider guide, and release
  runbook are all updated bilingually; ADR 0002's profiles design is marked superseded by ADR 0004.
