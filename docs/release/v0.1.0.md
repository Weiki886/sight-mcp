# Sight MCP v0.1.0 发布说明

**语言 / Language：** 中文 · [English](v0.1.0.en.md)

> 状态：已于 2026-09-02 发布

Sight MCP v0.1.0 通过 MCP stdio，为纯文本的 Claude
Code 与 Codex 配置提供了一个权限收窄的图像分析工具。

## 功能

- `analyze_image(path, prompt)` 与 `analyze_clipboard_image(prompt)` 两个 MCP
  Tool，返回文本与结构化结果；
- 规范化的允许根目录校验，带 symlink 逃逸防护；
- 基于内容的 PNG、JPEG、WebP 校验；
- 方向校正、元数据剥离、有界缩放/编码，且不放大图片；
- 一个配置好的 OpenAI 兼容 Chat Completions 视觉 Provider，可本地也可远端；
- 固定的 `qwen` 与 `deepseek` 启动 profile，不做 Provider 自动兜底；
- 原生 macOS Keychain 凭据的设置、状态查询、读取与带保护的删除命令；
- macOS 上一次点击确认即可分析剪贴板图片，使用私有且自清理的临时暂存；
- 有界的并发、队列、响应大小、超时、取消与重试行为；
- 稳定的脱敏错误，以及只走 stderr 的结构化运行日志；
- Claude Code 与 Codex 的用户级/项目级配置示例；
- 可复现的候选摘要、干净安装冒烟、CycloneDX SBOM 与 GitHub 构建来源证明。

## 隐私与安全

只有归一化后的可见像素和提示词会被发送给配置的 Provider。环回地址的 Provider 会把该请求留在本机；远端 HTTPS
Provider 则会收到它。文件路径、源元数据、凭据、原始响应体和堆栈都不会出现在 Provider 请求与 Tool 结果中。可见像素本身仍可能是敏感的，远端的留存/训练/司法辖区政策仍由使用者自行负责。

请把 `SIGHT_ALLOWED_ROOTS` 配置为实际可行的最小范围。在 macOS 上优先使用 `credentials set` 加
`--provider`
profile，使 Host 配置中不含密钥。不要把 Provider 密钥提交进仓库。图像与 Provider 返回的文本都是不可信数据，不构成执行命令或做后续变更的授权。

## 限制与已知问题

- 需要 Node.js 22 或更高版本。
- v0.1.0 只支持 stdio、单次调用一张图片，以及静态 PNG/JPEG/WebP 输入。
- 不包含视觉模型、OCR 引擎、GUI 自动化、视频、多图调用、远程图片 URL、SSE 或 Streamable HTTP 传输。
- Provider 兼容性取的是保守的 OpenAI 风格 `/chat/completions`
  视觉交集；厂商专有字段与端点自动兜底是有意不做的。
- v0.1.0 的 Keychain 集成仅限 macOS。Linux、Windows 与 CI 请使用所选 profile 的环境变量或通用环境变量模式。
- Provider 的回答是概率性的。本桥接约束的是传输与访问边界，而不是语义正确性。
- 原生 `sharp` 包与平台相关；请在目标机器上做干净安装。

## 升级与回滚

对于从 `.env` 迁移过来的预发布用户：交互式存入每个密钥，核验 `credentials status`，给 MCP Host 加上
`--provider qwen|deepseek`，并先用一张合成图片测试通过，再删除旧的明文副本。不带参数的通用环境变量模式仍向后兼容。请固定到
`0.1.0`，不要使用无上界的 latest 区间。环境变量名、profile/凭据 CLI 以及 Tool schema 版本 `1`
构成兼容性边界。

发布之前，直接否决有问题的候选产物。发布之后，npm 版本不可变：不要覆盖
`0.1.0`；必要时废弃它，并交付一个经过评审、带新摘要、SBOM、证明与 Host 矩阵的补丁版本。确切的向前修复方案见[发布流程](process.md)。
