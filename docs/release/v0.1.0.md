# Sight MCP v0.1.0 release notes

> Status: prepared release notes; not yet published

Sight MCP v0.1.0 gives text-only Claude Code and Codex configurations a narrowly authorized image
analysis tool through MCP stdio.

## Features

- one `analyze_image(path, prompt)` MCP Tool with text and structured results;
- canonical allowed-root enforcement with symlink escape protection;
- content-based PNG, JPEG, and WebP validation;
- orientation correction, metadata stripping, bounded resize/encoding, and no enlargement;
- one configured OpenAI-compatible Chat Completions vision Provider, local or remote;
- fixed `qwen` and `deepseek` startup profiles with no automatic Provider fallback;
- native macOS Keychain credential setup, status, lookup, and guarded deletion commands;
- bounded concurrency, queue, response size, timeout, cancellation, and retry behavior;
- stable sanitized errors and stderr-only structured operational logs;
- Claude Code and Codex user/project configuration examples;
- reproducible candidate digest, clean-install smoke, CycloneDX SBOM, and GitHub build provenance.

## Installation and verification

```sh
npx -y @weiki886/sight-mcp@0.1.0
npm view @weiki886/sight-mcp@0.1.0 dist.integrity dist.tarball
```

Configure the host and Provider as shown in the [README](../../README.md). For a downloaded release
artifact, verify its published digest and provenance before installation:

```sh
shasum -a 256 weiki886-sight-mcp-0.1.0.tgz
gh attestation verify weiki886-sight-mcp-0.1.0.tgz --repo Weiki886/sight-mcp
```

## Privacy and security

Only normalized visible pixels and the prompt are sent to the configured Provider. A loopback
Provider keeps that request on the local machine; a remote HTTPS Provider receives it. File paths,
source metadata, credentials, raw bodies, and stacks are excluded from Provider requests and Tool
results. Visible pixels may still be sensitive, and remote retention/training/jurisdiction policies
remain the operator's responsibility.

Configure the narrowest practical `SIGHT_ALLOWED_ROOTS`. On macOS, prefer `credentials set` and a
`--provider` profile so the host configuration contains no key. Do not commit Provider keys. Image
and Provider text is untrusted data, not permission to execute commands or make follow-up changes.

## Limits and known issues

- Node.js 22 or newer is required.
- v0.1.0 supports stdio only, one image per call, and static PNG/JPEG/WebP inputs.
- It does not include a vision model, OCR engine, GUI automation, video, multi-image calls, remote
  image URLs, SSE, or Streamable HTTP transport.
- Provider compatibility is the conservative OpenAI-style `/chat/completions` vision intersection;
  vendor-specific fields and automatic endpoint fallback are intentionally absent.
- Keychain integration is macOS-only in v0.1.0. Linux, Windows, and CI use the selected profile's
  environment variable or generic environment mode.
- Provider answers are probabilistic. The bridge bounds transport and access, not semantic
  correctness.
- Native `sharp` packages are platform-specific; use a clean install on the target machine.

## Upgrade and rollback

For pre-release users migrating from `.env`, store each key interactively, verify
`credentials status`, add `--provider qwen|deepseek` to the MCP host, and test one synthetic image
before removing the old plaintext copy. Generic no-argument environment mode remains backward
compatible. Pin `0.1.0` rather than an unbounded latest range. Environment variable names,
profile/credential CLI, and Tool schema version `1` are the compatibility boundary.

Before publication, reject a bad candidate. After publication, npm versions are immutable: do not
overwrite `0.1.0`; deprecate it if necessary and ship a reviewed patch with a new digest, SBOM,
attestations, and Host matrix. See the [release process](process.md) for the exact forward-fix plan.
