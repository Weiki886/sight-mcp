# Sight MCP v0.2.0 发布说明

**语言 / Language：** 中文 · [English](v0.2.0.en.md)

> 状态：准备发布

Sight MCP
v0.2.0 的主题是**减少授权摩擦**：在不放松文件系统边界的前提下，把日常读图路径上的重复弹窗降到零。

## 新增

### 客户端工作区根目录自动发现

当连接的 MCP 客户端声明了 `roots` 能力（Claude
Code 即是）时，服务在初始化完成后自动请求工作区根目录，并将其纳入允许路径集合。工作区内的图片从此无需授权对话框。

- 后台请求，3 秒超时；能力缺失、协议不支持、超时等任何失败都静默降级，不阻塞工具调用；
- 仅接受 `file://` scheme，路径经 `realpath` 规范化且必须是真实目录；
- 文件系统根 `/` 与整个主目录被拒绝并告警，不予采纳；
- 嵌套根折叠为最小等价集合，与 `SIGHT_ALLOWED_ROOTS` 行为一致；
- 支持 `notifications/roots/list_changed`，工作区切换时自动刷新。

**兼容性说明：** `roots/list`
已于 MCP 协议 2026-07-28 版本（SEP-2577）标记废弃，SDK 在该协议 era 下不会发送此请求。因此该能力被实现为可选增强而非必要依赖，客户端不支持时服务完全正常工作。

### 会话内授权缓存

路径同时位于配置根目录和客户端工作区根目录之外时仍会弹出 macOS 授权对话框，但用户批准后，该路径的**父目录**会被记入进程内存缓存，同一会话中该目录下的后续读取不再弹窗。

这一层协议无关，是根目录自动发现不可用时的兜底免弹窗方案。安全约束：

- 仅缓存用户实际批准路径的父目录，从不向上提升；
- 文件系统根与主目录永不缓存，无论路径深度；
- 只存于进程内存，不落盘，重启即失效；
- 拒绝与取消都不写入缓存。

### 文档链接 CI 门禁

新增 `pnpm docs:check`，挂在 `pnpm run ci`
链首，校验双语文档的五条规则：切换链接跨语种且每份仅一条、正文同语种闭环、无死链、无绝对路径链接、副本齐备。

## 变更

- 发布脚本不再硬编码版本号，改为从 `package.json` 读取，后续发版只需改一处；
- `pack:check` 的版本断言从固定值改为「打包产物与声明版本一致」，并校验版本号格式合法。

## 修复

- 修复双语文档中语种切换链接自指向的问题（4 处），根因是 perl 的 `$.`
  行号计数器在多文件处理时不跨文件重置。

## 威胁模型

新增两条并配套测试：

- **FS-05：** 恶意或配置错误的客户端上报过宽的工作区根目录；
- **FS-06：** 会话授权缓存把一次批准放大成过宽的持续授权。

## 安装与校验

```sh
npx -y @weiki/sight-mcp@0.2.0
npm view @weiki/sight-mcp@0.2.0 dist.integrity dist.tarball
```

## 升级说明

从 v0.1.0 升级无破坏性变更，无需修改配置。工具契约、错误码与环境变量保持兼容。

升级后建议重启宿主中的 MCP 服务以加载新代码。
